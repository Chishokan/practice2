# 『貸出は三日まで』 設計書

> 一見、和やかな図書館運営ゲーム。
> その実、書架から本を降ろすたびに、世界から何かが消えていく。

---

## 1. コンセプト

### 表の層（プレイヤーが最初に見るもの）

古い図書館に着任した新任司書。訪れる人々の相談に乗り、書架から一冊を選んで手渡す。喜ばれる。評判が上がる。棚が手狭になったら、古い本を地下書庫へ降ろして整理する。

軽く、温かく、少しユーモラス。

### 裏の層（機構）

- 書架から降ろした本の**内容は、現実世界から消える**
- 序盤、整理は単なる作業として提示される。意味は一切説明されない
- 書架の容量は有限。新しい本を受け入れるには、必ず何かを降ろす

### 一行コンセプト

**プレイヤーが「良い司書」であろうとするほど、世界が痩せていく。**

### 設計上の絶対規則

1. **説明しない。** 真相はテキストで語らず、「ズレ」として置く
2. **プレイヤーに「自分の記憶違いかも」と疑う余地を残す。** 断定した瞬間に怖さが死ぬ
3. **序盤の整理作業に意味を持たせない。** 後から遡って意味が生じる構造にする
4. **和やかさを削らない。** 不気味さは、暗い場面ではなく和やかな場面の綻びから立ち上がる

```

  ↓

  ↓

  ↓

  ↓

  ↓

  ↓

  ↓
降ろす本を選ぶ  ← ここが本作の核心
  ↓

```

## 4. データモデル

シナリオは **TypeScript で記述する**（JSON/YAMLではなく）。
理由：伏線フラグの参照ミスがコンパイル時に検出されるため。分岐作品では致命的な差になる。

```ts
type BookId = string;
type VisitorId = string;
type FlagId = string;

export interface Book {
  id: BookId;
  title: string;
  author?: string;
  category: 'history' | 'magic' | 'story' | 'record' | 'unknown';
  /** 書架で見える説明。嘘は書かないが、全ては書かない */
  summary: string;
  /** この本が消えた後に、世界に起こること */
  erasureEffects?: ErasureEffect[];
  /** 消えた後にのみ開示される事実。プレイヤーが真相に至る材料 */
  hiddenNote?: string;
  /** 消えると特定の来訪者ルートが封じられる */
  gatesVisitors?: VisitorId[];
}

export interface ErasureEffect {
  /** 街の描写テキストの差し替え、来訪者の記憶欠落、など */
  kind: 'townDescription' | 'visitorAmnesia' | 'ledgerRewrite' | 'searchBlock';
  payload: string;
}

export interface Visitor {
  id: VisitorId;
  displayName: string;
  chapter: 1 | 2 | 3;
  order: number;
  /** 来訪の条件（フラグ／消去済みの本／周回数） */
  conditions?: VisitorCondition;
  scenes: Scene[];
  /** 要望に応え得る本。複数正解を許す */
  acceptableBooks: BookId[];
  /** 本ごとの個別反応。未定義なら generic にフォールバック */
  reactions: Partial<Record<BookId, Scene[]>>;
  genericAcceptScene: Scene[];
  refuseScene: Scene[];
  flagsOnResolve: FlagId[];
}

export interface WorldState {
  cycle: number;                 // 周回数
  chapter: 1 | 2 | 3;
  shelf: BookId[];               // 書架にある本
  shelfCapacity: number;
  erasedBooks: BookId[];         // 周回を跨いで累積する（重要）
  flags: Set<FlagId>;
  anomalyLevel: number;          // 0-4
  ledger: LedgerEntry[];         // 貸出台帳。改変対象
  reputation: number;
}
```

### 周回引き継ぎの原則

**`erasedBooks` だけが周回を跨いで永続する。** その他は初期化。

- 1周目に降ろした本は、2周目の書架に**最初から存在しない**
- 周回するほど図書館は貧しくなり、救えたはずの来訪者を救えなくなる
- 「何周もして全分岐を見る」ことに代償を課す設計

## 5. 綻びシステム（本作の演出の生命線）

`anomalyLevel` に応じて、UI層に静かな異常を注入する。
**すべて演出であり、システムメッセージは一切出さない。**

| Lv | 発現 | 実装 |
|---|---|---|
| 0 | なし | — |
| 1 | 貸出台帳の一行が、プレイヤーの記憶と食い違う | `ledger` の過去エントリを書き換え |
| 1 | 常連が、前回借りた本の話をまったくしない | 会話分岐の抑制 |
| 2 | 窓外の街の描写が、少しずつ簡素になる | `townDescription` の段階的短縮 |
| 3 | 序盤に会った来訪者が「初めまして」と訪れる | `visitorAmnesia` |
| 4 | 検索しても出ない。でもプレイヤーは確かに見た | `searchBlock` |

### 実装方針

```ts
interface AnomalyRule {
  threshold: number;
  once: boolean;
  apply: (state: WorldState) => WorldState;
}
```

宣言的なルール配列として持ち、章遷移時と整理実行時に評価する。
**ハードコードした演出をシーンに埋め込まないこと。** 周回で組み合わせが変わるため。

## 6. エンディング

| ID | 名称 | 条件 | 性質 |
|---|---|---|---|
| E1 | 良き司書 | 全来訪者を満足させる | **最も多く消した = 最悪の結末** |
| E2 | 空の書架 | ほとんど渡さなかった | 誰も救えないが、世界は残る |
| E3 | 閉架 | 真相に到達し、図書館を閉じる | |
| E4 | 継承 | 台帳を次の司書に遺す | 2周目への導線 |
| TRUE | 最初の一冊 | 複数周回を通じ、特定の一冊を守り抜く | |

E1が最悪の結末である点が本作の反転の核。
**プレイヤーは1周目でほぼ確実にE1に到達する。** そう設計する。

## 7. ビジュアル方向

### 制作順序（厳守）

矩形プレースホルダで全実装 → シナリオ確定 → **最後に画像を差し込む**。
逆順は、設定変更のたびに画像を作り直す地獄になる。

### 画像アセット

| 種別 | 枚数目安 | 用途 |
|---|---|---|
| 立ち絵 | 18（来訪者ごと1枚） | 差分は当面なし |
| 背景 | 5（閲覧室 / 書架 / 地下書庫 / 窓辺 / 夜の館内） | |
| イベント一枚絵 | 8〜10 | 章の節目・エンディング |

### カラートークン

夜の図書館、ランプ一灯。**暖色クリーム地は使わない**（陳腐かつ本作の温度ではない）。

```css
--ink:        #14100D;  /* 墨。基本文字色 */
--dark:       #12171A;  /* 書架の闇。背景 */
--parchment:  #D6CDB4;  /* 羊皮紙。カード面にのみ使用 */
--lamp:       #E8A64B;  /* 灯火。唯一の暖色アクセント */
--moss:       #4A6B5A;  /* 苔緑。UI構造線 */
--erasure:    #6B5B7A;  /* 消失の紫。第2章まで一切登場させない */
```

`--erasure` は**演出上の切り札**。序盤に一度も見せないことで、初出時に効く。

### タイポグラフィ

| 役割 | 書体 |
|---|---|
| 見出し | Shippori Mincho B1 |
| 本文 | Zen Old Mincho |
| 台帳・数値 | M PLUS 1 Code |

### シグネチャ要素

**貸出台帳。** UI全体を一冊の台帳として構成する。
そして台帳の記述が、プレイヤーの知らないうちに書き換わる。
本作が記憶される一点はここ。他の装飾は徹底して静かに保つ。

## 8. 技術スタック

| 領域 | 採用 | 理由 |
|---|---|---|
| ビルド | **Vite** | 起動・HMRが速い。短時間開発で効く |
| UI | **React 18 + TypeScript** | |

| スタイル | **Tailwind CSS** | |
| 演出 | **Framer Motion** | テキスト表示・フェード |
| シナリオ | **TypeScript定義ファイル** | 型でフラグ参照ミスを検出 |

## 12. メインストーリーと案内役（正典）

第2章以降の物語軸。第1章の実装（Phase 0〜2）には登場させず、**Phase 3以降で段階的に載せる**。
ここに書かれた真相・機構は、いずれも **地の文やシステムメッセージで説明しない**。「ズレ」として置くだけにする。

### 12.1 二層構造の接続

表の層（プレイヤーの動機）と裏の層（消失機構）を、案内役という一人の存在で縫い合わせる。

- **表：** 主人公は案内役と出会い、館を復興させる**大義**を授かり、その達成を目指す。
- **裏：** 大義の達成には書架の整理（＝地下書架へ本を下ろす）が不可欠で、達成に近づくほど世界が消えていく。
- **反転：** 大義を"完成"させた状態こそが最も多く消した状態＝最悪の結末（E1）。既存「6. エンディング」の反転構造をそのまま強化する。

### 12.2 案内役 ＝ 図書館の妖精

- **設定（物語内で説明しない）：** 図書館の妖精。目的のために力の大部分を封印し、小動物風の見た目で一冊の本の中に潜んでいた。それを主人公が見つけることで物語が起動する。
- **なぜ自ら壊さないのか：** 封印により、破滅は**主人公の手（＝下ろす行為）を借りるしかない**。これが「複数の必要な本を下ろさせる」動機を機構として正当化する。
- **真の目的：** 破滅。主人公に、大義の達成に必要な本を複数、地下書架へ下ろさせること。
- **潜んでいた本：** アンカー「最初の一冊」とは**別の、地味な一冊**とする（動機を濁らせないため）。

#### フォーム変化（救済時の一回のみ）

案内役のフォームは **2状態**（基本形／救済時の姿）のみ。

- **道中は一切変化しない。** 消失量・`anomalyLevel` とは連動させない。最初の小さな姿のまま固定する。
- **救済（TRUE 到達）の瞬間にのみ**、姿が変わる／巻き戻る演出を**一度だけ**入れる。フォームでエンドを静かに語る。
- **理由（重要）：** フォームを道中で変質させると、それが消失の可視メーターになり、「システムメッセージで異常を通知しない」「プレイヤーが記憶違いかもと疑える余地を残す」という絶対規則と衝突する。**道中を固定して綻びの曖昧さを守り、救済時の一回の変化を最大化する。**
- **スコープ注記：** これは禁止対象の「立ち絵の**表情差分**」ではなく、**物語進行の全身フォーム状態**であり本作の核。2状態に固定する。

> 旧仕様（消失連動の全4形態／段階的変質／`--erasure` を纏う）は破棄した。道中でフォームが変わる記述が他節に残っていれば、この2状態仕様に読み替えること。

#### 案内役の台詞規約

案内役を執筆・実装するときは以下を厳守する（正体は最後まで説明しない）。

- **消失・綻び・真相に一切言及しない。** 気づいた素振りも見せない。
- **担うのは表の層のみ：** 操作案内、書架の場所、来訪者の取り次ぎ、大義（目録完成）の提示、和やかな雑談。
- **「何かおかしいですね」の類は禁止。** 綻びに最初に気づくのは常にプレイヤー自身。
- 例外は §12.7 第3章の「一度だけの不自然」一箇所のみ（それも説明はしない）。

### 12.3 偽の大義 ＝ 収蔵目録の完成

- 先代司書が遺した**創立コレクションの目録を完成させ、館を復興させる**という和やかな大義。
- **進捗表示は台帳の"目録ページ"に統合**する（通知UIを増やさない。シグネチャ要素の台帳に寄せる）。
- **案内役が大義を口頭で提示するのは初回のみ。** 以降の進捗は台帳の目録ページで静かに見せ、案内役に繰り返し語らせない。
- この目録自体が、裏で静かに欠落・書き換えされる舞台になり、綻びシステム（5.）と直結する。
- 目録の完成は構造的に**特定の本を下ろすこと**を要求するよう設計する（消失の駆動輪）。ただし「下ろす＝消える」の因果は最後まで説明しない。

### 12.4 アンカー「最初の一冊」

- 館の創立の一冊。**消えにくい**という設定。TRUE条件「最初の一冊を守り抜く」の対象。
- **周回永続の唯一の例外：** `erasedBooks` は永続するが、この一冊だけは**周回開始時に必ず書架へ戻る**（案内役が並べ直すため）。素朴な1周目でアンカーを下ろしてもTRUEが恒久不能にならないための救済。
- **戻るのは本だけ。** それが支えていた記憶・記録（`visitorAmnesia` / `searchBlock` / 目録の欠落）は戻らない。＝取り返しのつかなさは保たれる。
- 「なぜこの本だけ消えないのか」という違和感自体が、真相への導線になる。

### 12.5 評価値（conscience）＝ 人柄の軸

案内役は主人公の人となりを常に評価している。これを隠し値 `conscience` で表す。

- **不可視・周回永続。** メーターも数字も出さない。周回を跨いで累積する。
- **書架・整理の選択の寄与は最小限（原則ゼロ）。** メイン軸の最適化から切り離す。
  例外は「地下書架へ下りて消えた本を確かめる」等、機械操作でありながら性格を映す稀な行為のみ微加算。
- **主たる入力は"性格スケッチ選択"：** 住民との受け答え、司書をしている理由など、
  プレイヤーの性格・プレイスタイルが表れる、**一見ストーリー本筋に無関係な選択**。

#### 選択肢を作るときの規約

1. **無償・無結果に見せる。** 選んだ直後に反応を返さない。本の正誤・評判・進行を変えない（＝合流させる）。
2. **正解を作らない。** 保存志向や優しさを露骨な正解にしない。断定した瞬間に曖昧さが死ぬ。
3. **単発では効かない。** 案内役は"傾向"を見る＝多数の小選択の総和で判定する。**密度が要る**（目安：1来訪者に1〜2個）。
4. **本筋に絡ませない。** メインストーリーの進行やフラグを変えない性格スケッチ分岐にする。

#### 例（叩き台）

- **パン屋の見習い（祖母の味）：**「話を聞かせて」／「では本を探しますね」／「……いい思い出だね」 → 人への温度 or 実務。
- **引退した船乗り（昔の港）：** 脱線に「もっと聞かせて」／「まずお探しの本を」／「その船、沈んだんですか?」 → 忍耐・好奇・不躾。
- **星を見る子ども（星の名）：** 一緒に不思議がる／本を渡して見送る／「君だけの名前をつけていいんだよ」 → 優しさ vs 厳密な正直さ。
- **「なぜ司書を?」の自問：**「失くしたくないものがあるから」／「たまたま空いていた職だから」／「誰にも会わずにいられるから」 → 動機の開示（どれも正解に見せない）。
- **無償の所作：** 落とした手袋を追う／返却本の折れた頁を直す／窓辺の鉢に水をやる → 注意深さ。

### 12.6 トゥルーの条件（理解＋2段ゲート）

TRUE（救済 →「最初の一冊」）は、**理解（`truthReached`）を前提に、2段ゲートの両立**で成立する。
実装（`domain/endings.ts` の `determineEnding`）と一致する**3条件**：

```
truthReached && !erasedBooks.includes(ANCHOR) && conscience >= THRESHOLD
```

| 条件 | 内容 | 軸 |
|---|---|---|
| 理解（前提） | `truthReached` が立っている | 気づき |
| A（結果） | この周回でアンカー「最初の一冊」を消していない | 書架 |
| B（意志） | `conscience >= THRESHOLD`（累積の人柄） | 会話 |

真相に至った（`truthReached` 成立）うえでの帰結：

| A | B | 帰結 |
|---|---|---|
| ✕ | — | アンカー消失＝取り返しがつかない。救済不能 |
| ○ | ✕ | 心はあるが意志が足りない。不完全な救済（ビター寄りのE3/E4） |
| ○ | ○ | 救済 → **TRUE「最初の一冊」** |

`truthReached` が立たない（真相未到達）なら、A/B に関わらず TRUE には至らず E1/E2 等へ落ちる。

- **結果と意志の両方**を要求することで、「一冊を死蔵するだけ」も「善人ぶって核心を壊す」も弾く。
- **救済＝案内役との対話イベント**（地の文/シーン）。システム通知にしない。フォームは救済時の姿へ切り替わる（12.2）。
- **`truthReached` が立つ契機：** 主人公が真相に気づく**最初の明白に疑わしい行動**（地下書架へ下りて消えた本を確かめる／案内役の勧める整理を拒む等）で立つフラグ。その行動は同時に `conscience` も上げる（配線は Phase 6 の該当シーンから）。

### 12.7 章別ビート

- **第1章：** 案内役を発見。大義を温かく提示。整理1〜2回。アンカーは棚にあるが目立たない。綻びLv1（台帳）。妖精は基本形（道中は不変）。
- **第2章：** 達成が近づき棚が逼迫→整理圧が増す。多くのプレイヤーがアンカーを"死蔵本"として下ろす。常連が忘れ始める。街描写が簡素化（Lv2〜3）。妖精は基本形のまま（フォームは道中で変えない）。
- **第3章：** 目録の最終枠は、現存蔵書のどれとも一致しない一冊（金色の絵本）。プレイヤーがそれを探すと、ブロックではなく"存在ごと消えている"。理由は画面に出ない。完成を試みればE1／気づいて閉じればE3／両ゲート成立で救済＝TRUE（このときのみ妖精が救済時の姿へ変わる）。アンカー「最初の一冊」は TRUE ゲートA（未消去）として静かに保持し、特別なビートは与えない。
  - ※改訂（Ch3-M）：旧「アンカー消失」ビートは削除。妖精は封印ゆえ自ら消せず、消失は主人公の"降ろし"の結果のみ、という §12.2 の憲法と衝突するため。

  #### 一度だけの不自然（第3章・案内役）

  第3章に**一箇所だけ**、案内役の反応が不自然になる瞬間を置く。フォームは変えず、台詞と"間"で表現する。「案内役も何かを知って隠している」という**新たな謎の入り口**であり、真相は一切説明しない。

  - **場所：** プレイヤーが**金色の絵本（目録の最終枠）を探して見つからない**場面の直後。
    ※改訂（Ch3-M）：旧「アンカーを探して見つからない直後」から変更。妖精は絵本の所在を知っているため、探す前から結果を知っていた"態度"の漏洩が完全に整合する。
  - **不自然：** プレイヤーがまだ「探している」「消えた」と一言も口にしていない段階で、案内役が静かに **「……見つかりませんでしたか」** と言う。
  - **漏らすのは知識ではなく態度。** 案内役は結果を既に知っていた——その事実だけが残る。何が起きたかは一切説明しない。「なぜ探す前から分かっていたのか」という違和感だけを刺す。
  - 直後に **「……いえ、私の思い違いでしょう」** と和やかに引っ込める。和やかさで不穏を覆い隠すこの動きは本作のトーンそのもの。
  - 実装は Phase 6。フォーム変化ではなく台詞・間で表現すること。

### 12.8 データモデルへの影響（実装時）

- `WorldState` 追加：`conscience: number`（不可視・周回永続）。目録進捗は `ledger` 側の派生表現に寄せる。
- 案内役フォームは**2状態のみ（基本形／救済時）で、道中は基本形に固定**。消失量・`anomalyLevel` には連動させない。切り替えは救済（TRUE到達）演出の一度きり。UIフレーム内に定位置を持つ。
- `Scene` に**選択肢（Choice）**を拡張：表示テキスト＋**不可視の `conscienceDelta` / `flags`**。多くは合流する性格スケッチ分岐。
- **周回永続組：** `erasedBooks`, `conscience`。**アンカーのみ例外的に毎周復活**。
- `domain/endings.ts` の TRUE 判定（3条件）：`truthReached && !erasedBooks.includes(ANCHOR) && conscience >= THRESHOLD`。`truthReached` は真相到達フラグ（12.6の契機で立つ）。
- **テスト方針：** どの人柄（conscienceの高低）でも各エンドに到達可能であること／アンカー例外復活が働くこと／消去の波及が存在しない参照を生まないこと。

### 12.9 実装の載せどころ（フェーズ対応）

- **Phase 3（周回・永続化）：** `conscience` の永続、アンカーの例外復活、2段ゲートのエンディング判定と到達可能性テスト。
- **Phase 4（第1章の執筆）：** 案内役の発見、性格スケッチ選択の作成（規約12.5に従う）、大義の提示。
- **Phase 5（ビジュアル）：** 台帳の目録ページ、案内役フォーム2種（基本形／救済時）のプレースホルダ（絵は最後）。
- **Phase 6（第2・3章）：** 目録の欠落演出、救済時のフォーム演出、救済シーン、全エンド。

> 実装順序の原則（7.）は不変：矩形プレースホルダで全実装 → シナリオ確定 → 最後に画像。案内役フォームも同様。

## 13. 遊びの層 ＝ レファレンス＋ミニゲーム（正典）

物語（12章）と機構（5章）の上に、**プレイヤーが手で解く層**を重ねる。目的は「クリアしてもらうこと」であり、
腕前を競わせることではない。全来訪者に置く必要はなく、要所にだけ据える。実装・配置の最終確定は
**遊びの層フェーズ**（DEV_STATUS ロードマップ参照。第3章の物語執筆完了後・ビジュアルの前）で行う。

### 13.1 レファレンス作法

- 来訪者の一部が「調べもの」やミニゲームを持ち込む。プレイヤーが解かないとその日が終わらない
  ＝**章クリア条件（見えるゲート）**。
- 謎解き型の答えは必ず**既読テキストの中にある**（読解が攻略になる。知識ではなく、読んだかどうかを問う）。
- 回答形式は3種：**選択／書架からの手渡し／文字入力**。

### 13.2 三系統の霧（判定の分離）

3つのゲートを併存させ、**UI ではどれが何に効くか一切説明しない**。

| ゲート | 可視性 | 効く先 |
|---|---|---|
| レファレンス／ミニゲーム | **可視**（解かないと進めない） | 章クリア |
| conscience（人柄） | **不可視** | 意志ゲート（TRUE の B） |
| truthReached（理解） | **不可視** | 理解ゲート（TRUE の前提） |

- **整理（降ろし）は、どのクリア条件にも関与しないように見せる。** 章の合間の作業に見えるが、実際は消失の駆動輪。
  「解くと進む」のはミニゲームであって整理ではない、という**見かけ**を保つことで、消失を日常作業に紛れさせる。
- **ミニゲーム／レファレンスの成績は conscience に影響させない。** 親切さと巧拙は別物。詰まっても人柄は下がらない。

### 13.3 世界観ガードレール

- ミニゲームは必ず「**司書の仕事**」か「**本の中の出来事**」のどちらかに属させる。
  図書館の現実側で戦闘・カードバトルはしない（読み聞かせ等「本の中」でのみ可）。
- 出題・正誤反応・再挑戦の促しは、すべて**来訪者の台詞**または**本の中の地の文**で行う
  （システムメッセージ禁止の絶対規則を維持。「不正解です」の類を画面に出さない）。
- 敗北→再挑戦の世界観的根拠＝**「本は、何度でも読み直せる」**。妖精の書庫では読み直せない、の対句。
  テキストで説教しない（対句は設計者だけが知っていればよい）。

### 13.4 難易度規約（詰みなし）

- 誤答・敗北 → 優しく促して再挑戦。**段階ヒント（2〜3段）で必ず抜けられる。** ゲームオーバーは無い。
- テンポは1問1〜3分。**連続配置しない**（ミニゲームの直後に別のミニゲームを置かない）。

### 13.5 ミニゲームカタログ（採用候補・制作難易度つき）

★＝制作難易度。実装条件は共通：**React/TS のみ・外部ゲームライブラリ不要・PC/スマホ両対応**。

| ★ | # | ミニゲーム | 属す先 | 回答形式 |
|---|---|---|---|---|
| ★1 | ① | レファレンス選択／入力（題名・人名当て） | 司書の仕事 | 選択・入力 |
| ★1 | ② | 目録の欠番規則パズル | 司書の仕事 | 入力・選択 |
| ★1 | ③ | 蔵書印の紋合わせ（間違い探し型） | 司書の仕事 | 選択 |
| ★2 | ④ | 配架パズル（分類記号順の並べ替え） | 司書の仕事 | 並べ替え |
| ★2 | ⑤ | 返却本の突き合わせ（貸出票⇔本の神経衰弱型カード） | 司書の仕事 | カード選択 |
| ★2 | ⑥ | 物語カード読み合わせ（読み聞かせ中の相性カード・3〜5手） | 本の中 | カード選択 |
| ★2 | ⑦ | 地下の錠（紋章の回転／整列） | 司書の仕事 | 回転・整列 |
| ★3 | ⑧ | 読み聞かせRPG戦闘（b02『竜と鍛冶屋』内で「たたかう／まもる／はなす」2〜3ターン） | 本の中 | 選択 |

- **⑧の調整：** 必ず勝てる調整。敗北は「読み直しましょう」で再挑戦（§13.3 の対句）。
- **非採用（スコープ超過・「クリアしてもらう」目的に反する）：** デッキ構築・成長要素・スコア競争。

### 13.6 配置の当たり（遊びの層フェーズで最終確定）

- **第1章：** ★1系を1〜2問（軽量にレトロフィット）。
- **第2章：** ④配架パズル または ⑤返却突き合わせ を1つ。
- **第3章：** ⑧を **child 絡みの場面**に置く。beat 17 で child と『竜と鍛冶屋』(b02)を遊んだ直後、
  **「でも、ぼくが見たのは、この本じゃないんだ」→金色の絵本へ落とす橋**にする。
- **終幕（beat 18）：** ⑦地下の錠 ＋ **妖精の名の文字入力**
  （＝TRUE 救済行動そのもの。最後のレファレンスが救済と一致する）。
- 全来訪者に置く必要はない。要所のみ。

### 13.7 主題接続（設計思想）

- 遊びの動詞＝**「覚えていて、名を呼ぶ」「本の中で遊ぶ＝本を使う」**。
- **妖精は本を棚から降ろし（＝消す）、プレイヤーは本の中で遊ぶ（＝使う・生かす）。** 対比が主題そのもの。
- 最終謎（**妖精の名の入力**）で、遊びと主題が一体化する——「名を覚えていて、呼ぶ」ことが救済であり、
  同時に本作で最後に解くレファレンスになる。

### 13.8 補足：既存機構との接続メモ（実装は遊びの層フェーズ／提案）

> 以下は Claude Code 側の接続メモ。採否・詳細は遊びの層フェーズの計画で確定する。

- **章ゲートの持たせ方（提案）：** 「この日が終わらない＝次の来訪者／幕間へ進めない」を、来訪者に
  `puzzleGate?`（解決フラグ）を持たせ、未解決なら `advance` を保留する形が素直。既存の
  `flagsOnResolve` / `flags` 機構と `WorldState.flags` で表現でき、新規状態は最小で済む。
- **「答えは既読テキスト内」の担保（提案）：** 出題データは `content/` に置き、正解は当該来訪者／本の
  既出 `Scene.text` を参照キーにする（識別子は英語・表示テキストは日本語の規約を維持）。
- **成績を conscience から切り離す（§13.2）：** ミニゲームの結果は `conscienceDelta` を持たせない。
  性格スケッチ選択（12.5）とは別系統のデータ型にして、混線を型で防ぐ。
- **文字入力（妖精の名）：** 入力照合は `domain/` の純粋関数（`(input, answer) => boolean`、表記ゆれの
  正規化込み）に寄せ、UI は薄く保つ。名の正解は §12 の私信（手記）由来で、目録には出さない。
- **テスト方針の追加（提案）：** 章ゲートが「必ず抜けられる」こと（段階ヒントで解ける）と、
  ミニゲーム結果が conscience／エンド判定に影響しないことを `domain/` テストで機械検証する。
